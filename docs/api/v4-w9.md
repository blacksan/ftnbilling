# v4 notes: W9 (live router data, interfaces, clients, overview, router actions)

Shapes are the ones of addendum L in `api-v1.md`; this file lists what was built and where it differs. All routes are new in v4, so they are registered under `/api/v1/routers/...` only (there is no `/sites` twin: `GET /sites/{id}/live` is 404). `?router=` and `?site=` both work on `/overview`. Roles: viewer for the three reads and the overview, operator for recheck and resync, owner for reboot.

## Data rules
- A router is read only through the fixed list `sites.LiveReadPaths`: `/system/resource`, `/system/health`, `/system/routerboard`, `/interface`, `/ip/address`, `/ip/dhcp-server/lease`, `/ip/arp`, `/interface/bridge/host`, `/queue/simple`. Never a caller-supplied path, never a write. Each row is cut down to named fields; no raw row and no secret-looking field is returned (a test checks the keys and plants secrets in the mock).
- Cache 5 s per router and view (`live`, `interfaces`, `clients`), concurrent callers share one read, one read is cut at 3 s. If the read fails, the last good answer (at most 60 s old) is served with `reachable:false`; after that the router part is empty and `reachable:false`. These calls never answer 5xx because the router is down: they answer 200.
- Interface rates are `(counter now - counter at the previous read) * 8 / seconds`. The first read of a router (and the first after a counter went backwards) has `rx_bps`/`tx_bps` null. Rates are therefore only meaningful if the same view is polled; poll every 5 s or more.

## GET `/routers/{id}/live`
`RouterLive` as in addendum L, with these details:
- `reachable`: false when the router could not be read (the `system` block is then zero/empty unless a stale copy was served). The store-side fields (`flats`, `revenue`, `equipment`, `open_alerts`, `provision`, `throughput`) are always filled.
- `system.model`/`serial` come from `/system/routerboard` (model falls back to the board name on a CHR); `temp_c` is `temperature`, else `cpu-temperature`, else null. `mem_used_bytes` = total - free.
- `wan.down_bps`/`up_bps`/`util_pct` are null unless the metrics collector has a port sample younger than 5 min; `util_pct` = max(down, up) / `cap_mbps`, one decimal. `wan.running` is the interface's flag. Down is the WAN's rx.
- `throughput`: last 3 hours, 36 buckets of 300 s, oldest first, `t` in RFC 3339 UTC, a bucket without a sample is null.
- `tunnel`: `handshake_age_s` from WireGuard, `rtt_ms`/`loss_pct` from the fleet probe of the last 10 min; each null when unknown.
- `flats.online` and `overview.online_now` count a flat as online when the collector rate is under 3 min old or the router last saw it under 3 min ago. `GET clients` also counts a flat that is in the bridge host table or has a dynamic complete ARP entry, so its `counts.online` can be higher.
- `unregistered_online` = devices without an account seen in the last 3 min. `onts_bound` = installed ONTs with an account; `equipment` counts non-retired OLT and ONT items of the router.
- `setup_state` is the derived v5 set-up state (`Manager.SetupStateOf`: `not_started`, `waiting_router`, `online`, `ready`; see `docs/api/v5-bootstrap.md`). There is no provisioning job any more.

## GET `/routers/{id}/interfaces`
`{items:[Interface], generated_at, reachable}` (`reachable` is additive). `role`: `tunnel` (type wg or `wg-ftn`), `wan`, `olt`, `bench` (the router's bench port), `customer` (the interface that holds the customer gateway address, else `br-hotspot`), else `other`. `last_link_up` is the router's own clock text, unchanged (no time zone), or null. `addresses` are the enabled `/ip/address` rows of the interface. Up to 5000 rows are read.

## GET `/routers/{id}/clients?q=&kind=all|flats|unregistered&online=true|false`
`{items:[Client], counts:{flats,online,unregistered}, truncated, generated_at, reachable}` (`truncated` and `reachable` are additive). `counts` are for the whole list before filtering. Another `kind` or `online` value is 400 `validation_failed`.
- `q` is a case-insensitive substring of tenant name, flat, code, IP, MAC (as `AA:BB:..`, and with any separators or none when q is only hex digits and `:-. `, 2+ digits), vendor and DHCP host name.
- Order: flats by flat label (natural, "Flat 2" before "Flat 10"), then unregistered devices (online first). At most 1000 items.
- `queue_limit` is `<down>/<up>` such as `20M/20M`, "" when the flat has no queue. `down_bps`/`up_bps` are the collector's rates (0 when no sample under 3 min old). `usage_*_bytes` are both directions, EAT day and month. `lease_status` for a flat is the reconciler's; the router's lease row refines it. `last_seen` is the reconciler's last sighting (null if none). Devices the router shows on a bound lease but the server has not yet noted are listed as unregistered.
- The merge uses `AccountRouterState`, the collector, `billing.Unregistered` and `billing.Vendor`; no extra router path.

## POST `/routers/{id}/actions/reboot` (owner)
Body `{confirm_name}`. Checks in this order: role (403 `forbidden_role`), router exists (404), the typed name equals the router's name exactly (case matters; only surrounding spaces are ignored; otherwise 400 `validation_failed`, `fields.confirm_name`), no other reboot of this router in flight (409 `bad_state`, "being rebooted right now"; there is no provisioning job to wait for), router connected (409 `bad_state`), 1 reboot per 10 min per router (429 `rate_limited` with `Retry-After`). Then `POST /rest/system/reboot` through `Inspector.Call`: 202 `{queued:true}`; the router answering with an error is 409 `router_refused` (and the 10-minute slot is given back); a connection cut while it reboots counts as success. Audited as `api: router <name> (<id>) reboot sent`. The limiter is in memory (a server restart resets it).

## POST `/routers/{id}/actions/recheck` (operator)
Runs the setup checks fresh (`Manager.Checks(fresh=true)`) and answers the `Checks` object of `sites/checks.go` (it carries `site_id`, so also `router_id`). Audited.

## POST `/routers/{id}/actions/resync` (operator)
202 `{queued:true}`. In the background: the IPoE reconcile, the queued per-account router tasks, a refresh of the device list. Audited.

## GET `/overview?router=`
`Overview` as in addendum L. Details:
- `greeting_period`: Africa/Nairobi (EAT): morning 05:00-11:59, afternoon 12:00-16:59, evening 17:00-21:59, late 22:00-04:59.
- `setup.steps` keys, in order: `mpesa`, `first_plan`, `router_joined`, `router_live`, `first_customer`, `whatsapp`; `pct` is `done*100/total` rounded down. `router_live`: the derived set-up state is `ready`. `href`s are `/admin/settings/mpesa`, `/admin/plans`, `/admin/routers`, `/admin/subscribers`, `/admin/settings/whatsapp`.
- `revenue`: real money only (not vouchers or admin grants), EAT day, previous day, calendar month; `spark_7d` has 7 daily totals, today last.
- `today`: newest first, at most 20: payments (`payment`, `unmatched`) and non-audit events (`expired`, `reminder`, `info`) since EAT midnight; `time` RFC 3339 UTC.
- `next` (only entries with count > 0, in this order): `routers_offline`, `unmatched_payments`, `new_devices`, `renewals`, `mac_conflicts`, `no_plan`, `router_tasks`.
- `renewals_48h`: active accounts ending within 48 h, soonest first, at most 50.
- `busiest_routers`: top 5 by WAN download now (then flats online); `online` = flats online on that router.
- `health.at_risk`: active accounts the router last saw more than 7 days ago (a flat never seen since the server started is unknown, not at risk); `churned`: expired more than 30 days ago; `expiring_7d`: active and ending within 7 days.
- `expiries_per_day`: 14 EAT days starting today; count of active accounts whose plan ends that day.
- `?router=` that does not exist is 404.
